# Roadmap

Ordered milestones (format: `~/.claude/VERSIONING.md`). Tagging is the user's call; `kind: experiment`, so a tag marks a step.

- **v0.2 - does the dyn gain keep growing with training budget?** Answered 2026-10-17: it halves per doubling (16M -> 32M -0.005, 32M -> 64M -0.0025; dyn stack 0.9765 / 1.0131 on parts 0 / 1, `docs/tiers_design.md` "novels40 at 64M windows"). Tag is the user's call.
- **v0.3 - is the stack worth scaling, or is it at its floor?** Answered 2026-10-18: not at its floor. d=384 beats d=256 by 0.014-0.018 in the stack at matched memory (`docs/tiers_design.md` "Width test"). Next milestone below.
- **v0.4 - how far does width go, and can the full memory be kept?** Answered 2026-10-19: yes to the memory (keys narrowed to 256 dims, `whiten_rank=256`, fit the full 125M-key memory at any width tried) and width still pays through d=640 (dyn stack on parts 0 / 1: d=256 0.9765 / 1.0131 at 64M windows, d=384 0.9694 / 1.0087 over 3 seeds, d=512 0.9568 / 0.9928, d=640 0.9459 / 0.9850; one seed each above d=384). The step gain per 128 of width is shrinking (0.014 -> 0.013 -> 0.011 on part 0; 0.013 -> 0.016 -> 0.008 on part 1) and the kNN saving over the model alone shrinks with it. d=768 did not train until 2026-10-20 (dispatch limit, fixed in `cubes()` in `src/gpu_step/mod.rs`; see the d=512 8-block entry). Detail in `docs/tiers_design.md` "Width test" through "d=640". Tag is the user's call.
- **v0.5 - what is the next lever once width flattens: depth, budget at the wide model, or key width?** Answered 2026-10-21: depth at matched step cost beats width (d=512 with 6 blocks, dyn 0.9409 / 0.9820, vs d=640 0.9459 / 0.9850; one seed each, margin 0.003-0.005). The 8-block run ties 6 blocks in the stack (0.9413 / 0.9821) while improving the model alone, so model scaling has saturated in the stack. Done: kNN weights retuned for the 6-block model, `128:0.4:30:7:100`, dyn 0.9782 / 0.9366 (-0.0038 / -0.0043 vs the old weights). The same weights on 8 blocks give dyn 0.9317 / 0.9715 (best), on d=640 nothing; the retune is per-model. Open: 8-block grid, depth beyond 8, key width above 256, seed repeats. Candidates: more blocks at d=512; extend the best model (d=640) to 32M windows from its checkpoint with `init=`; keys wider than 256 dims at d=512+ (rank 288 parked, full memory at d=384 needed rank 256); seed repeats of d=512 / d=640 to pin the best number.
- **v0.6 - does the stack keep improving with depth once the kNN weights are tuned per model?** Opened 2026-10-21. With the retuned weights the 8-block d=512 model (dyn 0.9317 / 0.9715) beats the 6-block one (0.9366 / 0.9782) by ~0.005, although the two tied under the old weights, so depth had not saturated. Test: train 10- and 12-block d=512 models (`scripts/train_eval_width.sh 512 8 1024 <seed> <blocks>`, ~6 h each), grid the kNN weights on each (`scripts/dyn_knn_ckpt.sh`), compare dyn stacks against 0.9317 / 0.9715. Done when a gain under 0.003 shows saturation, or depth keeps paying. Alternatives not taken: key width above 256 dims (VRAM-limited), 8-block seed repeat.
